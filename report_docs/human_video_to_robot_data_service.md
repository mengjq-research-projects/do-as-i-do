# 人类视频到机器人数据：能力、闭环与服务定位

日期：2026-08-11

## 1. 结论

本项目不应被定位为通用的“单目视频 3D 资产生成工具”。更准确的定位是：

> 将单目 RGB 人手-物体示范转换为结构化手物轨迹，并进一步转换为目标机器人在物理仿真中的参考轨迹，为机器人数据生成、策略训练和任务验证提供起点。

当前仓库已经打通：

```text
单目 RGB 人手-物体视频
  -> 手部、刚体物体和逐帧运动重建
  -> 数据清理、尺度与重力对齐
  -> Sharpa 灵巧手运动学重定向
  -> MuJoCo Warp 物理优化与回放
```

当前还没有打通：

```text
Isaac / Isaac Lab 标准化导出
  -> LeRobot / GR00T 训练数据
  -> VLA 或控制策略训练
  -> 实机闭环评估
  -> 失败数据回流和持续迭代
```

换言之，当前输出不是现成的 Isaac/LeRobot 训练数据，也不是可直接部署的机器人策略。

因此，现阶段可以销售的是有明确边界的**研究验证和本体适配服务**；完成 Isaac、标准数据格式和策略效果验证后，才适合销售“机器人训练数据产品”。

## 2. 当前 retargeting 实际做了什么

### 2.1 输入

Retargeting 不直接读取原始视频，而是读取 reconstruction 阶段的结果：

- MANO 手部网格、21 个手部关键点、腕部姿态和有效帧；
- 刚体物体网格；
- 逐帧物体 6-DoF 位姿；
- 单目深度推断得到的尺度；
- 相机坐标系中的重力方向；
- 主交互手信息：左手、右手或双手。

### 2.2 数据预处理

`process_dataset.py` 将视觉重建结果转换为适合机器人重定向的参考数据：

1. 对手腕和物体轨迹进行异常速度检测；
2. 对无效帧、丢失帧和短时跳变进行插值；
3. 将相机坐标系旋转到重力对齐的 Z-up 坐标系；
4. 将初始物体位置移到统一工作区，并保证轨迹不会落到地面以下；
5. 统一物体网格、手部网格、手腕、指尖和物体位姿的尺度与坐标；
6. 保存机器人重定向所需的关键点参考轨迹。

这一阶段解决的是“视觉结果可否作为统一、连续的机器人参考”，不是机器人控制问题。

### 2.3 物体碰撞几何

`decompose_mesh.py` 使用 CoACD 将物体网格分解为凸碰撞体。当前流水线还会对薄壁网格进行 2 mm 加厚，并将碰撞体外扩 2 mm，以减少重建网格破洞和接触不稳定带来的仿真失败。

视觉网格用于显示，凸分解网格用于碰撞。它们不是精确 CAD，也没有从视频恢复真实材料、质量、摩擦系数或惯量。

### 2.4 MuJoCo 场景生成

`generate_scene.py` 生成包含机器人手、物体、碰撞对和接触参数的 MJCF 场景。当前仓库内置的机器人资产是：

- `sharpa`：实际的目标灵巧手；
- `mano`：用于参考和诊断的人手模型。

场景可以是左手、右手或双手。代码还可以添加一个 UR3e 手腕圆柱近似体来检查腕部附近的碰撞，但它不是完整 UR3e 机械臂模型。

### 2.5 运动学重定向

`solve_ik.py` 使用 mink 求解逆运动学：

- 跟踪人手腕部的位置与方向；
- 跟踪五个指尖的位置；
- 使用姿态正则避免机器人手进入不合理构型；
- 第一帧先求腕部，再加入指尖目标；
- 后续帧以上一帧为初值连续求解。

这一阶段输出机器人手的关节位置和速度参考。需要特别说明：

- 人手和机器人手的关节角不是一一复制的；
- 优先保留的是腕部、指尖和物体的任务空间关系；
- 物体位姿在 IK 阶段被直接设为视觉参考，并不是 IK 求解得到的动态结果；
- 当前优化的是带 6-DoF 浮动腕部的机器人手，不是完整机械臂；
- UR3e 机械臂关节轨迹由部署阶段根据腕部轨迹再次求解。

### 2.6 物理优化

`optimize_physics.py` 在 MuJoCo Warp 中运行基于采样的滚动时域优化。Do as I Do 当前配置包含：

- 1,024 个并行控制样本；
- 每个规划步骤最多 32 次优化；
- 3 秒规划窗口；
- 手腕、手指和物体位姿跟踪奖励；
- 速度与终端跟踪奖励；
- 手物穿透惩罚；
- 基于“物体在手中 / 物体在支撑面”的几何状态约束；
- 开始阶段固定物体、关闭重力，让手先形成稳定抓持；
- 在规划样本中施加随机力和力矩，寻找对小扰动更稳定的交互。

最终保存：

- 机器人和物体的 `qpos`；
- 速度 `qvel`；
- 控制序列 `ctrl`；
- 物体位置与方向跟踪误差；
- MuJoCo 场景、运行配置和可视化结果。

### 2.7 “物理可行”在当前项目中的准确含义

当前结果表示：轨迹在指定的 MuJoCo 模型、碰撞几何、摩擦和质量假设下，可以经过物理优化进行回放，并比纯 IK 结果更能维持手物关系。

它不等于：

- 已恢复视频中的真实接触力；
- 已获得真实物体的质量、惯量和摩擦；
- 已验证电机力矩、温度、通信延迟和实机安全限制；
- 已生成能够处理扰动和视觉变化的闭环策略；
- 可以不经测试直接下发实机。

当前默认配置中的显式 `contact_guidance` 处于关闭状态。手物状态主要由距离、碰撞和物理仿真推断，不应对外表述为“从 RGB 视频恢复了真实接触标签或受力”。

## 3. 当前学术与工业界的闭环

机器人基础模型和具身智能团队正在形成以下数据闭环：

```text
数据来源
人类视频 + 遥操作 + 机器人自主执行 + 合成数据
        |
        v
数据处理
筛选、分段、语言标注、状态/动作对齐、质量评分
        |
        v
机器人化
3D/4D 重建、动作表示、retargeting、本体适配
        |
        v
仿真与扩增
碰撞验证、物理优化、域随机化、轨迹扩增
        |
        v
模型训练
模仿学习、VLA 后训练、世界模型、RL
        |
        v
评估与部署
仿真成功率、实机成功率、吞吐量、安全与人工接管率
        |
        v
失败数据回流
补采长尾场景、重新训练、再次部署
```

不同数据各自解决不同问题：

| 数据 | 优势 | 缺口 |
|---|---|---|
| 网络和人类视频 | 数量大、任务和物体丰富 | 没有机器人关节状态和动作 |
| 遥操作数据 | 动作与机器人本体严格对齐 | 昂贵、慢、受硬件和操作员限制 |
| 仿真数据 | 可并行、可获得完整状态 | 依赖资产和初始轨迹，存在 Sim2Real 差距 |
| 实机自主数据 | 最接近部署分布 | 早期失败率高，采集和安全成本高 |

Do as I Do 所处的位置，是在人类视频和机器人训练数据之间增加一个显式、可检查的“机器人化”步骤：

```text
人类视频
  -> 手物 4D 参考
  -> 目标机器人轨迹
  -> 物理仿真结果
  -> 训练数据或任务初始化
```

它不会替代整个闭环。它最可能减少的是早期示范采集、任务初始化和仿真场景准备成本。

## 4. 为什么这些团队可能需要我们的服务

### 4.1 人类视频丰富，但机器人动作标签稀缺

网络视频或普通相机录制的视频没有机器人关节状态、末端动作和控制信号。客户即使拥有大量视频，也通常不能直接把它们作为行为克隆数据使用。本项目可以把其中一部分转成有尺度的手物运动和目标机器人参考。

### 4.2 每增加一种机器人本体，都需要重新建立动作映射

不同灵巧手的自由度、指长、关节限制和控制接口不同。跨本体模型正在进步，但特定硬件仍需要动作空间定义、适配数据和验证。Retargeting 可以成为同一人类示范到不同机器人之间的中间层。

### 4.3 仿真扩增需要高质量种子，而不是只有静态资产

Isaac Lab、GR00T-Mimic 一类系统可以从少量示范扩增出大量轨迹，但前提是已经有场景、物体、机器人和初始动作。我们的输出可以作为种子轨迹和交互场景，而不只是一个静态物体网格。

### 4.4 基础模型仍然需要客户任务数据

截至 2026 年，Google Gemini Robotics、NVIDIA GR00T 和 Physical Intelligence 都展示了跨任务或跨本体泛化，但其公开流程仍需要针对新任务、新环境和新硬件进行示范收集或后训练。通用模型降低了样本量，没有消除本体适配和客户私有数据需求。

### 4.5 显式 3D 管线提供了可检查性

端到端 VLA 可以直接联合训练人类视频与机器人数据，但出现失败时很难判断问题来自视频、动作表示、机器人本体还是策略。显式重建和仿真能够显示手、物体、目标机器人及其误差，适合研究比较、数据质检和任务可行性分析。

这些理由说明存在服务机会，但不能替代商业验证。最终必须证明至少一项客户指标得到改善：更少的遥操作示范、更短的新任务准备时间、更高的策略成功率，或者更低的无效数据比例。

## 6. 不同团队如何使用我们的结果

### 6.1 灵巧操作团队

**客户提供：** 目标任务视频、目标灵巧手模型、关节限制和控制接口。

**我们提供：** 手物参考、目标灵巧手 IK 轨迹、物理优化轨迹、场景与质量报告。

**使用方式：**

1. 作为模仿学习或 Diffusion Policy 的示范初值；
2. 作为强化学习的参考轨迹和 tracking reward；
3. 用于比较不同抓型、手型或 retargeting 算法；
4. 从一个人类示范生成多组物体姿态和物理参数变化的训练任务。

**价值指标：** 实机示范减少量、仿真成功率、抓持稳定性、目标物体轨迹误差。

### 6.2 VLA 与机器人基础模型团队

**客户提供：** 目标 VLA 数据格式、目标机器人、少量真实机器人示范和任务语言。

**我们提供：** 经筛选的人类视频、结构化 3D 手物标签、目标机器人参考动作、质量标签；未来输出 LeRobot/GR00T episode。

**使用方式：**

1. 将人类视频作为预训练或联合训练数据；
2. 将机器人化轨迹作为动作监督或中间表示；
3. 使用视频的动作、物体和质量标签构建数据采样策略；
4. 与少量真实机器人数据共同后训练，减小人机域差距。

**价值指标：** 相同真实机器人数据量下的成功率提升，或达到相同成功率所需的真实示范减少量。

这里必须做 A/B 实验。仅交付轨迹数量不能证明 VLA 数据价值。

### 6.3 Sim2Real 团队

**客户提供：** 目标机器人数字孪生、物体尺寸/质量范围、任务成功条件和实机限制。

**我们提供：** 仿真种子轨迹、物体碰撞资产、接触场景、参数化变体和回放结果；未来提供 Isaac Lab 环境。

**使用方式：**

1. 以重定向轨迹初始化模仿学习或 RL；
2. 随机化物体姿态、质量、摩擦、相机和光照；
3. 生成轨迹变体并筛除穿透、掉落和越界样本；
4. 在仿真验证后，仅把通过样本用于实机测试。

**价值指标：** 首次实机成功率、仿真到实机性能下降、实机试错次数和人工接管率。

### 6.4 跨本体学习团队

**客户提供：** 两种或更多机器人模型、统一任务定义和期望动作表示。

**我们提供：** 同一人类示范对应的多机器人轨迹，以及共享的手物任务空间参考。

**使用方式：**

1. 构造“一段人类动作、多种机器人执行”的配对数据；
2. 研究关节空间、末端空间和相对动作空间哪种表示更易迁移；
3. 对新本体做少样本后训练；
4. 将手物几何关系作为不同机器人之间的公共监督。

**价值指标：** 新本体所需示范数量、零样本或少样本成功率、不同本体间的任务完成差距。

当前仓库只完成 Sharpa 的主要路径。多本体服务必须为每种机器人新增模型适配、关键点映射、碰撞配置、控制接口和独立验收。

### 6.5 机器人数据与评测团队

**客户提供：** 人类视频库或机器人示范库、数据规范和质量阈值。

**我们提供：** 视频筛选、阶段性质量分数、可视化、失败分类和物理回放。

**使用方式：** 在训练前剔除无交互、手物出画、跟踪跳变、IK 不可达、严重穿透或仿真掉落的数据。

**价值指标：** 有效数据率、人工审核时间、训练失败率和问题定位时间。

## 7. 建议的服务形态

### 服务 A：可行性验证

- 范围：10 段受控视频、一个刚体任务、Sharpa 手；
- 交付：重建结果、MuJoCo 重定向、三层回放和失败报告；
- 目标：判断客户任务能否被当前方法处理；
- 当前成熟度：最接近现有代码能力。

### 服务 B：目标机器人适配试点

- 范围：20–50 段视频、一个任务族、一个客户机器人；
- 交付：本体适配器、仿真轨迹、QA 报告和标准化 episode；
- 目标：减少客户重新采集示范或手工编写初始轨迹的工作量；
- 前置建设：目标机器人适配，以及 Isaac 或客户仿真器接入。

### 服务 C：训练数据效果试点

- 范围：客户真实机器人数据，加上转换后的人类视频数据；
- 交付：训练集、基线策略和 A/B 评估；
- 目标：证明成功率、数据效率或任务准备时间得到提升；
- 前置建设：LeRobot/GR00T 格式、训练管线和实机评估协议。

不建议首先建设一个面向任意视频、任意机器人和任意任务的通用平台。每个试点应固定一个本体和一个任务族，先证明结果价值。

## 8. 验收指标

每个客户项目应在开始前共同定义以下指标：

1. **输入通过率**：符合拍摄规范的视频中，有多少能够完成重建；
2. **重建质量**：手物分割、物体重投影、轨迹连续性和尺度误差；
3. **IK 质量**：腕部、指尖和物体的任务空间误差，以及关节限位违反次数；
4. **物理质量**：物体跟踪误差、最大穿透、掉落比例和完整回放比例；
5. **数据质量**：转换为目标格式的 episode 比例和人工审核通过率；
6. **策略价值**：加入转换数据前后的仿真和实机任务成功率；
7. **商业价值**：减少的遥操作时长、人工标注时长和新任务准备周期。

前四项只能证明流水线工作；第六和第七项才能证明客户愿意持续付费。

## 9. 能力边界与风险

- 当前优先支持单手或简单双手操作单个刚体；
- 单目深度存在尺度和手物距离歧义；
- 不恢复完整场景、障碍物和物体关节结构；
- 柔性、透明、镜面和严重遮挡物体不在稳定范围内；
- 当前主要目标本体是 Sharpa，物理后端是 MuJoCo Warp；
- Isaac、LeRobot 和 GR00T 输出仍需开发；
- 输出是参考轨迹和仿真控制序列，不是具备视觉反馈的闭环策略；
- 网络视频通过率低，应优先使用客户授权、按规范拍摄的视频；
- HaWoR、MANO、SAM3 和 SAM3D 等依赖需要单独完成商用许可证审查。

## 10. 当前最合理的定位

近期对外表述：

> 我们帮助灵巧手、人形机器人和 Robot Learning 团队，把受控的人手-物体 RGB 示范转换为目标机器人可检查的参考轨迹和物理仿真数据，用于任务可行性验证、仿真初始化、本体适配和训练数据实验。

不应表述为：

> 任意网络视频都可以自动变成可直接部署的机器人策略。

中期产品方向应是：

```text
视频准入与质量评分
  + 人手-物体 4D 重建
  + 多机器人本体 retargeting
  + Isaac / MuJoCo 物理验证
  + LeRobot / GR00T 数据导出
  + 策略收益 A/B 评估
```

只有当客户实验能够证明它减少真实示范成本或提高策略性能时，这条技术链才从研究能力变成可重复销售的产品。
